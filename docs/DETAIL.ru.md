# Плагин управления MySQL/MariaDB（kore-plugin-db-mysql）

## Обзор

Плагин действительно обследует экземпляры MySQL/MariaDB, перечисляет базы, выполняет запросы только для чтения и считывает ключевые показатели; начиная с L2 добавляется повседневное управление — создание/удаление базы и пользователя, права, экспорт/импорт. Он не включает драйвер MySQL и бинарники mysql/mysqldump (G-17): вызывает `mysql` / `mysqldump` хоста через `os/exec` и зависит только от `kore/pkg/pluginapi`. Отсутствие клиента возвращает `E_UNSUPPORTED` без скрытого переключения.

## Поверхность протокола

Протокол `kore.plugin.v1`, `lifecycle=lazy`, `depth_level=production`, возможность `system:admin`, взаимно исключает `db-postgres`. Основные методы: `instances` / `databases` / `query` / `status` (только чтение) и методы записи L2 `createDatabase` / `dropDatabase` / `createUser` / `dropUser` / `grant` / `changePassword` / `exec` / `export` / `import`. Контракт конфигурации `db-mysql.config.get` / `db-mysql.config.set` описывает экземпляр по умолчанию; пароли идут только через файл с правами 0600 или переменную окружения, а `config.get` возвращает лишь `***`.

## Основные возможности

Клиенты `mysql` / `mysqldump` по умолчанию ищутся в PATH; `KORE_MYSQL_BIN` / `KORE_MYSQLDUMP_BIN` задают абсолютные пути. Приоритет конфигурации: `config.json` > окружение > значения в коде, файл `<KORE_STATE_DIR>/config.json` (атомарная запись 0600), изменение действует со следующего вызова в том же процессе (`restart_required=false`). `db-mysql.exec` использует двухуровневое подтверждение: `INSERT/UPDATE/DELETE/REPLACE` требуют лишь `confirm=true`, а `DROP/TRUNCATE/ALTER/CREATE/...` — ручного ввода первых двух ключевых слов инструкции.

## Граница безопасности

Право записи не открыто по умолчанию: оно требует объявления `system:admin` и повторной проверки во время выполнения; при отсутствии — `E_UNAUTHORIZED`; удаление базы или пользователя требует `confirm=true`. Границы чтения и записи строго разделены: `query` сохраняет список только для чтения, запись есть только в явных методах управления, а пароли передаются через окружение/файл 0600, никогда в argv, логи или ответы. Ошибки зондирования разделяются по причине: действительно недоступные экземпляры сохраняют `reachable:false`, а локальные ошибки fork/exec возвращают общее `E_UPSTREAM` без частичной таблицы.

## Сборка и проверка

Ежедневная проверка — локальный `make check` (gofmt → go vet → go test -timeout 200s); перед выпуском `make dist` дважды с совпадающим sha256. Граничные и параллельные случаи (например, 8 одновременных созданий/удалений) находятся в `tests/boundary/`; атрибуция ошибок имеет положительные и отрицательные самодоказывающие случаи. Версия 0.5.2; взаимно исключает `db-postgres` — не включать запись для обоих одновременно.
